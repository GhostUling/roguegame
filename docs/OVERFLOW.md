# 溢流 OVERFLOW —— 新模式设计稿

> 状态：**卡池 25 张**（18 张参数 / 小改 + 7 张新系统卡）。已落地：第三模式骨架（`cardPool` 旋钮 + 敌人伤害/速度随时间的曲线）、七张新系统卡（棱镜塔、网格裁决、镜像分身、亡者编队、超频协议、射击回响、裂空光矛）。未落地：`handSize` / `deathPenalty*` / `runDurationSec` 旋钮、溢流词缀、图鉴的溢流分节。**「闭合棱线」与「轨道囚笼」已废弃**（见 §9）。实现偏差记在 §5.8。
>
> 定位：给「不讲道理的强化」一个正当的容器。它不承担平衡，只承担演出；标准模式的 25 条强化一条都不受影响。

## 0. 一句话

**五分钟的强度失控实验场。** 敌人每分钟换一种花样变强，你每分钟拿一张不讲道理的卡，比的是这五分钟里堆出了多离谱的一台机。

## 1. 设计目标

1. **爽是唯一指标。** 卡池的伤害卡直接翻倍而不是 ×1.35，是故意的。
2. **不污染标准池。** 卡池来源做成模式旋钮。`赌徒协议`、`玻璃风暴` 这种东西一旦流进标准跑就会毁掉它。
3. **不可中断。** 死亡不清空构筑，只扣时间。所以这个模式敢放「最大生命变成 1」的卡——它不是自杀，是笑话。

## 2. 与标准模式的结构差异

```ts
// game/core/modes.ts —— GAME_MODES.overflow
// 前置：GameModeDef.accent 的联合类型要先加上 'amber'（现为 'cyan' | 'fuchsia'）。
{
  id: 'overflow',
  name: '溢流',            // 中文显示名，用于模式卡与角标
  tag: 'OVERFLOW',         // 拉丁副标签
  desc: '反应堆越过临界点。敌人每一分钟换一种花样，你每一分钟拿一张不该存在的强化。',
  pilotSlots: 1,          // 不做双子：屏幕已经够乱，会看不清任何一张卡的演出
  wingSpacing: 0,
  spawnMultiplier: 4.5,   // 有东西才能碾
  maxAlive: 260,
  growthScale: 3.0,       // 敌人 HP 曲线陡度（现有旋钮）
  pooledHp: false,
  accent: 'amber',
  // ---- 本模式新增的旋钮 ----
  cardPool: 'overflow',   // 卡池来源：'standard' | 'overflow'
  handSize: 4,            // 每次升级四选一（标准是三选一）
  deathPenalty: 'time_penalty',
  deathPenaltySeconds: 10,
  runDurationSec: 300,    // 本模式**有终点**，300 秒结算
}
```

`runDurationSec` 是这个模式的骨架：因为跑是有终点的，强度膨胀才有意义——玩家比的是「这五分钟我堆到多离谱」，而不是「我能活多久」。

## 3. 敌人也要变强

这是本模式的难点：卡池的强度上限是 ×50 级，**敌人的数值永远追不上**。所以敌人强化分两条腿走路——

> **数值曲线只负责「前期不无聊」，词缀负责「后期有威胁」。**

### 3.1 数字曲线（随时间连续上涨）

现状：`enemyHpFor(def, t, growthScale)` 会缩 HP，但 `spawnEnemy` 里 `speed: def.speed, damage: def.damage` 是**写死的常量**，全游戏敌人都不会越打越痛。所以要在数据层给 `EnemyTypeDef` 补两个 `hpGrowthPerMin` 的兄弟字段（数值随类型而异：`speeder` 涨得快、`tank` 涨得慢），模式的 `threatScale` 只负责整体倍数：

| 项 | 曲线 | t=300s 时 | 归属 |
|---|---|---|---|
| HP | `hp × (1 + t/120 × hpGrowthPerMin × 3.0)` | ×6.25（以 chaser 计） | 现有 `growthScale` 旋钮推到 3.0 |
| 伤害 | `damage × (1 + t/60 × damageGrowthPerMin × threatScale)` | ×1.5 | **新增** `EnemyTypeDef.damageGrowthPerMin` |
| 速度 | `speed × (1 + t/60 × speedGrowthPerMin × threatScale)` | ×1.25 | **新增** `EnemyTypeDef.speedGrowthPerMin` |
| 密度 | 出怪间隔下限 0.2s → **0.12s**（现有曲线已经随 `gameTime` 递减） | — | 模式旋钮 |

`threatScale` 是与 `growthScale` 对称的新模式旋钮（HP 用 `growthScale`、伤害与速度用它）。**溢流取 1.0**——曲线本身已经够陡，不必再乘。上表所有数字都是 `threatScale = 1` 时的值。

⚠️ **速度曲线的硬上限**：引擎的单帧步长最大 0.24s（3× 倍速），位移约 63px，已经接近碰撞判定的极限（仓库里记着这条技术债）。再乘 1.25 会开始出现穿模。**二选一：要么把 300 秒档的实际倍率压到 ×1.15 以内，要么本模式不开放 3× 倍速。**

### 3.2 溢流词缀（每一分钟换一种花样）

这是「变强」的**主要**手段，也是这个模式最花哨的部分。词缀从 60 秒开始逐个加入并且**永久叠加**：

| 时刻 | 词缀 | 效果 | 视觉 |
|---|---|---|---|
| 00:00 | — | 常规 7 种敌人 | — |
| 01:00 | **晶壳** Chitin | 每只怪带一层等于其 30% 最大生命的护盾，护盾破碎时向四周溅射碎片 | 外圈套一层半透明多边形 |
| 02:00 | **裂殖** Mitosis | 死亡时裂成 2 只更小更快的同类 | 死亡瞬间分成两半（`hive` 已有先例） |
| 03:00 | **过载** Charged | 移速 +40%，身体拖出残影 | 拖尾 |
| 04:00 | **殉爆** Volatile | 死亡时留下 90 半径爆炸，**对玩家造成伤害** | 死亡时红圈一闪 |
| 05:00 | **终局** Judgement | 全部词缀同时生效 + 终结 BOSS | 屏幕边框变色 + 警报音 |

到第 4 分钟，一只怪身上同时挂着晶壳、裂殖、过载、殉爆——它打不死、还会分裂、追得上你、死了还炸你。**这就是这个模式后期的威胁来源**，不需要靠数值去追玩家的 ×50。

词缀表放 `core/enemyTypes.ts`（与 `SPAWN_BRACKETS` 并列，`{ at: number; affix: AffixId }[]`）；敌人对象需要新字段（`shieldHp` / `affix` 标记）。前三档是纯参数与小改，`殉爆` 需要在 `killEnemy` 加一次爆炸。

### 3.3 BOSS 节奏与终局

标准模式是 120 / 240 / 360 / 480 秒各一只。本模式压缩到**每 60 秒一只**，五分钟共 4 只 + 1 只终结 BOSS；终结 BOSS 用 `boss` 定义再乘 `enemyHpFor` 的 300 秒档，并把它的弹幕环从 16 发提到 24 发。

## 4. 卡池规范

沿用标准池的 House Rules：**四字中文名 + 英文名**、五个分类（ballistic / energy / defense / summon / tactical）、多级值进 `LVL_*` 表且 `statDiffText` 与 `apply` **同源**、**每一级都必须真的改变玩家状态**（`__tests__/upgrades.test.ts` 的载荷测试会拦）、图鉴 `levels.length === maxLevel`。

**故意破例两处**：

1. **数值不追求彼此等价**——伤害卡是相对乘 ×2.2，不是 ×1.35。
2. **稀有度放开**——epic / legendary 可以占多数。这个池子不需要给 common 留位置。

卡池单独放一个文件（`game/cards/overflowUpgrades.ts`），`getRandomUpgrades(player, levels, pool)` 按模式分发。**标准池一行不改。**

### 5.8 与设计稿的偏差（实现时定的）

1. **赌徒协议** 从「×2 / 清零」改成「免费进阶已有强化」。原方案会让 `upgradeLevels` 倒退（见旧护栏 #4），卡面等级与实际效果必然对不上；改成单调进阶就从根上避开了这个坑，代价是少了一点赌博感。
2. **玻璃风暴** 的卡片文案删掉了「死亡只扣时间，所以这不是自杀」这句承诺。`deathPenalty` 还没实现（见 §9 未落地项），卡池文案不能承诺引擎做不到的事——那正是仓库里「图鉴承诺了、引擎里没有」那类技术债。等 `deathPenalty` 落地后再把这句话补回去。
3. **棱镜塔** 的伤害做成了逐级阶梯 ×0.8 / 1.0 / 1.2，而不是稿子里的固定 ×0.8。固定值会让三级卡里有两级只缩短一个 25 秒的计时器，升级手感太薄。
4. **网格裁决的「僵停」是新加的硬定身**，不是复用手感更软的冰冻减速。敌人原有的 `frozenTimer` 只按 `cryoSlowMultiplier`（0.65）减速，用它当「眩晕」会让卡片文案对不上实际效果（标准池的 `chain_lightning` 3 级就有这个历史遗留问题）。这一张新增了 `Enemy.stunTimer`，速度直接归零。
5. **亡者编队设了 24 的上限**，稿子写的是「不设数量上限」。复活的单位是有索敌、有绘制的独立 actor，在 4.5× 出怪率之上再叠一个无上限的种群，是这个模式唯一还能打穿帧预算的地方。另外**它只做「追最近的敌人 + 接触伤害」，不复刻 `sniper` / `charger` 的完整状态机**——「保留生前攻击方式」需要一整套友方 AI，成本远大于这张卡的收益，所以保留的是体型、颜色和咬合力。
6. **时停期间的行为做了统一规定**：`freezeTimer` 只冻结**敌群**（刷怪、移动、敌方子弹）；玩家自己的一切——机体、炮台、分身、友军、掷出的长矛——照常运转。这样「全场静止」的读法变成「世界停了，你还在杀」，而不是把自己也停住。
7. **裂空光矛的形态改了三个来回**（设计者逐轮反馈）。原本是**瞬间横扫 140° 的激光** → 反馈「不像长矛」；改成**掷出的长矛**后仍不对，因为速度只有 8px/帧、还带 10 段拖尾——看起来像「一颗带尾迹的弹」，而不是「一根长矛撕开地板」；于是提到 34px/帧并删掉拖尾，结果又「太细、也确实太快」。**定稿**：速度 **20px/帧**（子弹是 11；飞完全场约 1.8s，有速度但不至于一眼就没了），**彻底不带拖尾**，矛身加粗到半宽 11px、命中半径同步到 22px（判定跟着画面走），并在矛头**原地**画一层光晕给它重量感（画在矛身上，不是拖在身后）。唯一的痕迹是地板上的裂缝：每 26px 一个节点、**存活 2.0s**（比矛本身的 1.8s 长），节点沿飞行方向绘制、长度是间距的 1.8 倍，所以相邻节点连成**一条连续裂缝**；裂缝由「9px 暗芯 + 两侧 2.4px 亮缘 + 一根稳定岔裂」构成——**加粗与暗芯正是「撕开地板」和「地上有道光」的分界**，也是「太细」的根因。矛身贯穿（每具身体一次）×2.5 / 3 / 3.5；裂缝每 0.35s 切一次小怪 ×0.22 / 0.28 / 0.34，BOSS 免疫。三级强度来自「掷得更快（6 / 4.5 / 3s）」。**实现细节**：缝合节点到上限时用「丢最旧的」而不是「拒绝最新的」——一条裂缝从中间被挖空，比整体变短难看得多。
8. **超频协议加了一条硬规则：只有武器击杀计数**（设计者要求）。技能自己打死的敌人、以及友军（亡者编队）打死的敌人都不回灌冷却——否则技能会自己续自己，永远不停。为此引擎新增了伤害来源标记（`DamageSource`），`damageEnemy` 默认记 `weapon`，技能的伤害源（剑矛、奇点、熔核、闪现、冲撞、Gamma 弹幕）显式标 `skill`，友军接触标 `ally`，`killEnemy` 只对 `weapon` 结算。**已知边界**：少数绕过 `damageEnemy` 的直接扣血点（超新星、卫星、排斥、链电、铁卫反伤、冰爆、次元虹吸）各自显式声明了自己的来源，但将来新增这类直接扣血点时也要顺手声明，否则会沿用上一个来源标记。
9. **射击回响按「不堆伤害」原则调过**：重放弹 ×0.3 / 0.4 / 0.5（总量 1.3 / 1.4 / 1.5×），逐级主要改变的是回响延迟 0.35 / 0.3 / 0.25s。同时最多 8 波在队列里，避免快速射击把 130 发子弹上限撞破。

## 6. 结算与表现

**我方单位统一标记（已实现）**：炮台 / 分身 / 复活的友军身上都套同一枚青色虚线环 + 上方尖角，色值与线宽定义在 `game/render/friendlyMarker.ts` 一处，三处渲染共用。判定标准是「扫一眼就知道这个多边形是谁的」——敌人是深色实心多边形，只有我方带环。棱镜塔同时放大到半径 14（底座六边形 + 22px 炮管），以便和飞行中的弹药区分开。

**新增特效的落位（已实现）**：`裂空光矛` 的撕裂痕迹是**地面危害**，排在绘制第 4 步（与熔核同一步，在所有会动的东西之下），所以它铺满地面也不会盖住怪；长矛本身与光束同一步（第 11 步），复用已有的紫色位。两个新特效都只用 ≤2px 描边 + 淡出，**没有新增任何全屏覆盖层**——全屏覆盖层仍然只有 `超暴击` 白闪与 `网格裁决` 紫网格两处。

- **HUD 需要新增**：剩余倒计时（本模式有终点线）、**当前生效的溢流词缀**（一个图标条，这是玩家判断「该不该跑了」的唯一依据）、连击数（`连击加速` 需要它可见）。
- **GameOver / 结算面板**（复用现有的 `victory` 状态）：本模式结算展示「这一局堆出的卡组」+「最高单次伤害」+「总伤害」。**最高单次伤害**是爽池的记分牌。
- **不显示血条百分比**：`玻璃风暴` 让血条失去意义，改为显示「已死次数」。

## 7. 护栏

1. **爽卡绝不能溢进标准模式。** 这正是 `cardPool` 必须做成模式旋钮、而不是「往全局池里加卡」的原因。
2. **子弹上限会被撞破。** 引擎在 130 发处硬截断（`updateProjectiles` 开头），`无限扇面 + 全向倾泻 + 子弹繁殖` 三张叠起来必然撞上，**表现是子弹凭空消失**。要么把上限抬高并把「一次性截断最老的 130 发」改成**按剩余寿命淘汰**，要么别把这三张同时放进池子。
3. **速度曲线与 3× 倍速不能并存**（见 3.1）。
4. **`赌徒协议` 若按原方案（×2 / 清零）实现会让 `upgradeLevels` 倒退**：清零一条已有卡时，它在图鉴与卡片预览里的等级要跟着回落，否则「卡面写着 Lv.3、实际效果是 Lv.0」。**实现时改成了单调进阶来规避**（见 §5.8）。

## 8. 落地清单

**模式（照 `docs/CONTRIBUTING.md` 的「加一个模式」清单）**
`core/types.ts` 联合类型 → `core/modes.ts` 一行 → `__tests__/modes.test.ts` 旋钮断言 → `StartScreen` 模式卡（新强调色 `amber` 需在 `ACCENT_CLASSES` 补一条）→ 选人界面单槽 → `HUD`（倒计时 / 词缀条 / 连击）→ 结算面板。

⚠️ **两处必须先修，否则这个模式会「静默失效」**（现码里第三个模式根本进不去）：

1. `App.tsx:178` 是 `const mode: GameMode = modeForPilots(twinId)`——**模式完全由「是否选了第二台机」推导**。溢流是单机，所以它会拿到 `'standard'`，而 `modeForPilots` 也只会返回 `'standard' | 'twin_link'`。要么让它接一个显式选定的模式参数，要么让 `App` 直接用它自己已经持有的 `mode` 状态。
2. `modes.ts:75` 的 `modeOfPlayer` 不看 `player.gameMode`，而是 `isPaired(player) ? 'twin_link' : 'standard'`。引擎的 `mode()`、`pilots.getTwinPositions` 全走它，所以非双子的溢流跑会**整套读成标准模式**——`spawnMultiplier`、`maxAlive`、`growthScale` 全部悄悄退回 1 / 95 / 1。它必须改成「以 `player.gameMode` 为准，未知才回落 standard」。

**卡池**
新增 `game/cards/overflowUpgrades.ts`（独立表 + 自己的 `LVL_*`）→ `getRandomUpgrades` 按 `cardPool` 分发 → 图鉴为溢流池单开一节（`levels.length === maxLevel` 的断言同样适用）→ 挂机测试覆盖新池的每一级。

**敌人**
`core/enemyTypes.ts` 给 `EnemyTypeDef` 补 `damageGrowthPerMin` / `speedGrowthPerMin`（与 `hpGrowthPerMin` 并列，同一条数据层）→ 新增 `AFFIX_TABLE` 词缀时间表 → `Enemy` 补 `shieldHp` 与词缀标记 → `spawnEnemy` 读伤害/速度曲线与词缀 → `killEnemy` 加裂殖与殉爆。

## 9. 建议分期

- **第一期：骨架 + 敌人曲线 + 前两档词缀 + 18 张「参数 / 小改」卡。** 这一期就能玩，而且能立刻验证「五分钟强度失控」这个核心假设到底爽不爽。
- **第二期：新系统卡 + 后三档词缀（过载 / 殉爆 / 终局 BOSS）。** 放在核心手感被确认之后再投入。

进度：**卡池 25 张**（18 张参数 / 小改 + 7 张新系统卡），其中 **棱镜塔、网格裁决、镜像分身、亡者编队、超频协议、射击回响、裂空光矛** 已实现。剩余未落地：`handSize` / `deathPenalty*` / `runDurationSec` 三个旋钮、溢流词缀、图鉴的溢流分节、以及「表现层」（HUD 倒计时 / 词缀条 / 连击数、结算面板）。

**两张卡已废弃**：

- **「闭合棱线」Seal Line** 不实现：玩家反馈「画出来的线」不好玩，且它需要一条新的玩家轨迹管线与自交判定，收益不划算。
- **「轨道囚笼」Orbit Cage** 已实现过又删掉：它的定位是「拿掉直线弹、换成贴身的轨道弹」，实测与这个游戏的手感冲突——玩家看到的就是「武器没了」；而且原实现按「一颗弹道 = 一颗轨道弹」算，十台机体的弹道数全是 1，等于把武器换成一颗看不见的光点。修好之后仍然不好玩，所以整张卡连同 `orbitCage.ts` 一起删除，不留半成品（这次删得很干净，`grep` 全仓库无残留）。**教训**：凡是「替换普攻」形态的卡，都要先确认替换掉的东西在 260 只怪的画面里仍然读得出来是一个武器。

**不要一次做完。** 如果五分钟的骨架本身不成立，其余卡全是白写的。
